# 05. Деканат обрабатывает заявки, объявления, уведомления

**Дата:** 06.11.2026 · **Промпт:** «так давай продолжим работу»

ИИ сам выбрал следующий шаг по PLAN.md: замкнуть главный сценарий жюри «подать заявку → увидеть статус» со стороны деканата.

## Что сделано
- Таблица допустимых переходов статуса (`src/lib/request-flow.ts`): из «Новой» — в работу или отказ; из «В работе» — готово / нужны уточнения / отказ; и т.д. Сервер отклоняет любой переход не из таблицы.
- Очередь деканата: вкладки по статусам со счётчиками, фильтр по типу, просроченные — красным.
- Карточка заявки: данные студента, что просит, действия с подтверждением; «Готово» требует место выдачи, «Отклонить» и «Нужны уточнения» — комментарий.
- Студент отвечает на «Нужны уточнения» — заявка возвращается в работу.
- Каждое действие — уведомление студенту человеческим языком.
- Объявления: деканат — факультету / курсу / группе, руководитель — своим студентам; адресаты берутся только из области доступа автора.
- Уведомления: «Прочитать всё», фильтр непрочитанных, открытие отмечает прочитанным (редирект только на внутренние ссылки — без открытого редиректа).
- Список студентов факультета с поиском, долгами и активными заявками.
