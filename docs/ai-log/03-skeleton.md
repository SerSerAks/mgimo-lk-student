# 03. Каркас: вход, роли, база, импорт расписания

**Дата:** 06.11.2026 (по плану 08–09.11, сделано раньше)
**Инструмент:** Claude Code, встроенный браузер (проверка UI и безопасности), Docker, Prisma.

## Ключевой промпт

«Да, к каркасу» — после утверждения SPEC.md. Вся постановка задачи для ИИ лежала в CLAUDE.md и docs/SPEC.md, поэтому промпт короткий: агент сам прочитал правила.

## Что сделал ИИ

- Next.js 15 + TypeScript + Tailwind + shadcn/ui, токены DESIGN.md (navy, Montserrat с кириллицей, скругления).
- PostgreSQL в Docker, схема Prisma: 24 модели (Person → Enrollment → оценки/заявки/ВКР, портфолио, уведомления).
- Вход: argon2id, сессия в httpOnly-cookie (в БД только sha256 токена), лимит 5 неудачных попыток за 5 минут, одинаковая ошибка для «нет логина» и «неверный пароль», проверка хеша даже для несуществующего логина (против перебора логинов по времени ответа).
- `src/lib/access.ts` — все правила доступа в одном месте; чужой объект → 404.
- Разовый импорт РУЗ: 1964 занятия трёх реальных групп, поля преподавателей отброшены белым списком.
- Seed: 8 аккаунтов для жюри + 10 массовки, пароли случайные, сохраняются в локальный файл вне git.
- Экраны: вход, «Сегодня», расписание на неделю, оценки, заявки и карточка заявки, уведомления, профиль; для сотрудников — очередь заявок деканата, студенты руководителя, выпускники кафедры.
- `npm run test:access` — 11 автоматических проверок правил доступа.

## Ошибки ИИ и как исправили

| Что пошло не так | Как исправили |
|---|---|
| `create-next-app` не ставится в непустую папку | Создали во временной папке и перенесли файлы |
| npm 11 заблокировал install-скрипты Prisma — движок не скачался | Разрешили явно только 4 известных пакета (`allowScripts`) |
| Docker Compose: «project name must not be empty» из-за кириллицы в имени папки | Задали `name: dekanat` в compose-файле |
| ИИ передал компоненты-иконки из серверного кода в клиентский — так в Next нельзя | Иконки передаются строкой |
| Кнопка «Выйти» не работала: в новой версии shadcn кнопка по умолчанию `type="button"` | Нашли в браузере (у кнопки type=button), исправили, правило записали в CLAUDE.md |
| Текущая пара дублировалась в блоке «Изменения» | Исключили из списка |
| После ошибки входа форма стирала логин | Логин возвращается в форму |

## Деплой (06.11.2026)

**Промпты:** «что брать» (скриншоты тарифов Aeza), выбор Ubuntu, IP сервера, домен `lkstudenta.ru`, «готово».

- ИИ отговорил от веб-хостинга за 1 ₽ (там только PHP, без Node.js и своей PostgreSQL) и выбрал VPS MSKs-1 на месяц.
- Пользователь прислал root-пароль в чат. ИИ **не стал его использовать**: создал SSH-ключ, пользователь сам добавил его на сервер командой `ssh-copy-id`, затем ИИ отключил вход по паролю. Пароль из чата стал бесполезен.
- Сервер: брандмауэр (22/80/443), swap 2 ГБ, Docker. Caddy выпускает HTTPS автоматически.
- Секреты базы сгенерированы на сервере и не покидали его.
- На боевой базе: `test:access` 11/11, 19 из 19 паролей — argon2id.
- ИИ не вводил пароли на боевом сайте — вход проверяет пользователь.

| Что пошло не так | Как исправили |
|---|---|
| Домен зарегистрирован, но без A-записей — Let's Encrypt не выдаёт сертификат | Запасной адрес `83-141-92-172.sslip.io` с HTTPS; Caddy сам получит сертификат для домена, когда появится DNS |
| Хук безопасности Claude Code остановил создание файлов деплоя как «опасную команду» | ИИ перечислил, что меняется, и план отката, после чего повторил |
