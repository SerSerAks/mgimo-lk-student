# 02. Направления МГИМО и переход между ступенями

**Дата:** 06.11.2026
**Инструмент:** Claude Code, встроенный браузер, pdf.js (CDN) внутри браузера, Python для сборки CSV.

## Ключевые промпты (дословно)

1. «а можно подтягивать реальное расписание с https://ruz.mgimo.ru/ruz/main (или по правилам нельзя)?»
2. «важно что надо продумать как сделать чтоб студент плавно перетекал с бакалавра в магистратуру, а из магистратуры в аспирантуру: спарси все направления обучения и факультеты: [3 PDF приёма 2026 + страница научных специальностей]»

## Что сделал ИИ

- Разобрал правила конкурса по расписанию: парсинг открытых данных разрешён, но «не подключай к реальным системам» и «никаких реальных ФИО» → решение: разовый импорт без преподавателей.
- Извлёк текст из 3 PDF прямо в браузере через pdf.js, собрал `docs/content/programs.csv`: 120 строк (33 бакалавриата, 67 магистратуры, 20 научных специальностей).
- Проверил данные контрольными суммами: бюджет и договор по каждой ступени совпали с итогами в PDF.
- Спроектировал сквозной путь: модель Person → Enrollment → PortfolioItem, экран «Мой путь», планировщик «Что дальше?», карта траекторий `trajectories.md`.

## Ошибки ИИ и как исправили

| Что пошло не так | Как исправили |
|---|---|
| `curl` скачал вместо PDF HTML-заглушку защиты от ботов (13 КБ, одинаковая для 3 файлов) | Открыли сайт во встроенном браузере, загрузили PDF через fetch уже с пройденной проверкой и разобрали pdf.js в странице |
| Первый fetch из браузера тоже вернул пустой ответ | Проверка защиты ещё не завершилась; повтор после загрузки страницы прошёл |
| В тексте PDF цифры разорваны пробелами: «1 16», «54 6» | Восстановили по смыслу и подтвердили сверкой сумм с итоговыми строками PDF |
| ИИ вставил новый раздел SPEC перед разделом 9 — нумерация пошла 8, 10, 9 | Перенумеровали |

## Что сделано вручную

- Найдены ссылки на PDF приёма и страницу специальностей.
- Постановка задачи «плавного перехода» между ступенями.
