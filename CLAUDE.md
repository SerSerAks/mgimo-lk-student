# CLAUDE.md — правила проекта для ИИ-агентов

Этот файл читают Claude Code, Cursor и любые другие ИИ-ассистенты перед работой с проектом. Копия для агентов без поддержки CLAUDE.md — `AGENTS.md` (ссылается сюда).

## Что за проект

Конкурсный прототип **личного кабинета студента** МГИМО: «цифровой деканат будущего».
**Только кабинет студента**: войти может лишь студент. Сотрудники (деканат, руководители, кафедры) есть в базе только как справочные данные — экранов и входа для них нет. Полная версия с ролями сотрудников — отдельный проект `/Users/serseraks/Личный кабинет` (репозиторий mgimo-dekanat-concept).
Это **концепт для конкурса, не официальный сервис МГИМО.** Всё в кабинете вымышлено, кроме открытых данных (структура факультетов, сетка пар, названия дисциплин).

Ключевые документы, читать перед задачей:
- `PLAN.md` — план, этапы, календарь, принятые решения.
- `docs/SPEC.md` — что на каждом экране. **Источник правды по функциям** — разделы про студента; разделы про сотрудников относятся к полной версии.
- `docs/research/mgimo-open-data.md` — открытые данные МГИМО, что подтверждено, что допущение.
- `docs/content/` — тексты, справочники, вымышленные данные.
- `DESIGN.md` — цвета, шрифты, токены (визуальный язык mgimo.ru).

## Роли

Только `student` (уровень: `bachelor` / `master` / `postgrad`). Вход для остальных ролей закрыт в `src/app/actions/auth.ts` и `getCurrentUser`.

**Демо-движение** вместо сотрудников — `src/lib/demo-flow.ts`: заявка, поданная в кабинете (`autoFlow`), сама идёт «Новая → В работе (1 мин) → Готово (ещё 2 мин)»; заявка научному руководителю получает ответ через 1 мин. Кнопки «Ускорить (демо)». Срабатывает при открытии страниц (`requireStudent`), фоновых процессов нет.

## Стек (не менять без согласования)

- Next.js (App Router) + TypeScript (strict).
- Tailwind CSS + shadcn/ui, иконки lucide-react, шрифт Montserrat.
- PostgreSQL + Prisma.
- Сессии в httpOnly + Secure + SameSite=Lax cookie; пароли — argon2id (или bcrypt, cost ≥ 12).
- Деплой: российский хостинг (Timeweb Cloud / Amvera), секреты только в переменных окружения.

## Безопасность — нарушать нельзя

1. **Каждый запрос данных фильтруется по пользователю из сессии**, а не по id из URL или тела запроса. Шаблон: `where: { id, studentId: session.userId }`. Чужой объект → 404, а не 403 (не раскрываем факт существования).
2. Все правила «студент видит только своё» — в одном файле `src/lib/access.ts`, а не размазаны по страницам.
3. Пароли не хранятся и не логируются в открытом виде. Хеш — только argon2id/bcrypt.
4. Ключи (БД, ИИ-API, секрет сессии) — только `process.env` на сервере. Никаких `NEXT_PUBLIC_` для секретов. `.env` в git не коммитим, есть `.env.example` с пустыми значениями.
5. ИИ-помощник вызывается только с сервера; в промпт передаются данные **только текущего студента**.
6. Защита от перебора пароля: ограничение попыток входа.
7. Ввод пользователя валидируется на сервере (zod).

## Данные

- **Только вымышленные данные.** Никаких реальных ФИО, номеров зачёток, e-mail студентов и преподавателей МГИМО. Открытое расписание можно использовать как образец (дисциплины, время, аудитории), но преподаватели — вымышленные.
- Расписание: только разовый импорт из РУЗ скриптом `scripts/import-ruz.ts`, поля преподавателя вырезаются. Кабинет в рантайме к ruz.mgimo.ru не обращается.
- Формат групп как в МГИМО: `1МО-01`, `3МП-01`, `1МагГУ-01`.
- Сетка пар — два графика (см. research, раздел 3). Учёба 6 дней, недели чётные/нечётные.
- Где данные — допущение (шкала оценок, перечень справок), это помечено в research и в коде комментарием `// ДОПУЩЕНИЕ:`.

## Интерфейс

- Mobile-first: всё работает с ширины **360 px**. Нижняя навигация на телефоне.
- Цвета и шрифт — из `DESIGN.md` (navy `#162256`, Montserrat). Скругления: 4px кнопки/поля/бейджи, 8px карточки/модалки.
- Высота интерактивных элементов ≥ 44px.
- У каждого списка — пустое состояние, у каждой загрузки — skeleton, у каждой ошибки — понятный текст и действие.
- Язык интерфейса — русский, без канцелярита: «Справка готова, заберите в 214 каб.» вместо «Статус заявки изменён на "Исполнено"».
- На экране входа и в подвале — плашка «Концепт для конкурса. Не официальный сервис МГИМО». Официальный логотип МГИМО не используем.
- Порядок работ: сначала функции на базовых компонентах shadcn/ui с токенами DESIGN.md, полировка дизайна — отдельным этапом (17–18.11).

## Как работать

- Перед кодом прочитай соответствующий раздел SPEC.md. Если в SPEC нет ответа — спроси, не придумывай.
- Маленькие шаги: одна фича → проверка в браузере (десктоп + 360 px) → коммит.
- Коммиты на русском, в повелительном наклонении: «Добавь экран расписания».
- После каждой фичи: пройди сценарий руками и попробуй открыть чужие данные подменой id.
- **Журнал:** ключевые промпты, ошибки ИИ и как их исправили — в `docs/ai-log/`. Это часть сдачи на конкурс.
- Не добавляй зависимости без нужды; у каждой проверяй лицензию (MIT, Apache-2.0, OFL, ISC — можно).

## Команды

```bash
docker compose up -d        # локальный PostgreSQL (порт 5434), пароль из .env
npm run dev -- -p 3001      # приложение на http://localhost:3001 (3000 занят полной версией)
npx prisma migrate dev      # применить изменения схемы prisma/schema.prisma
npm run db:seed             # пересоздать тестовые данные; пароли → .demo-accounts.local.md
npm run import:ruz          # разовый импорт расписания РУЗ → data/ruz-snapshot.json (только вручную)
npm run test:access         # проверка «каждый видит только своё» и демо-движения — после любых изменений access.ts / demo-flow.ts
npx tsc --noEmit && npm run lint && npm run build   # перед коммитом
```

## Где что в коде

- `src/lib/auth.ts` — сессии, `requireUser` / `requireStudent`. `src/lib/access.ts` — все правила доступа.
- `src/app/(student)/…` — экраны студента. `src/lib/demo-flow.ts` — демо-движение заявок и ответов руководителя.
- `src/config/grading.ts` — шкала оценок (ДОПУЩЕНИЕ).
- `prisma/seed.ts` — тестовые данные. `scripts/import-ruz.ts` — импорт расписания.

## Известные ловушки

- Кнопки shadcn (`base-nova`) по умолчанию `type="button"` — в формах всегда пиши `type="submit"`. Они же не передают `name`/`value` в FormData: несколько действий в одной форме — через скрытое поле, заполняемое по onClick.
- После `prisma migrate dev` перезапусти `npm run dev`: dev-сервер держит в памяти старый Prisma Client (ошибка PrismaClientValidationError).
- Из `layout.tsx` нельзя экспортировать ничего, кроме компонента (ломает типы Next.js) — общие константы в отдельный файл.
- Миграции: `migrate dev` не работает в неинтерактивном режиме при предупреждениях → `prisma migrate diff --from-schema-datasource … --to-schema-datamodel … --script` в новую папку миграции + `migrate deploy`.
- Иконки в навигацию передаются строкой (`icon: "home"`), не компонентом: серверный компонент не может передать функцию клиентскому.
- Не запускай `npm run build` при работающем `npm run dev`: сборка перезаписывает `.next`, dev-сервер падает с `Cannot find module './NNN.js'`. Лечится остановкой dev и удалением `.next`.
- В docker-compose задано `name: lkstudent` — отдельная база от полной версии.
